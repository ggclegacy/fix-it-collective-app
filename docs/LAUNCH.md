# Next phase: production activation

The existing Vercel project `fix-it-collective-app` is linked to `ggclegacy/fix-it-collective-app` and serves the public platform preview. It is not a live business launch. Accounts, private preference storage and scheduling still use the local SQLite adapter, which intentionally refuses to run on Vercel. See [Provider experiences](PROVIDER-EXPERIENCES.md) for the implemented provider portals and their hosted fallbacks.

1. Confirm actual studio/team names, professional profiles, service offerings, prices, durations, buffers, working hours, location, timezone, contact details, approved photos, and cancellation/deposit policy. Replace the centrally marked sample catalog and remove the preview banner only after launch validation.
2. Connect a durable PostgreSQL database, implement the repository adapter and migrations, and retain database-level conflict exclusion and atomic booking. Provision staff identities through an invitation/verified-identity process. Add email verification, account recovery, stronger abuse protection, and role/location-specific permissions. Configure `APP_ORIGIN`, secrets, backups, and retention rules.
3. Integrate payment checkout and deposits with verified, idempotent webhooks. Decide booking holds, unpaid/expired state handling, refunds, cancellation fees, tipping, taxes, and receipts. No card fields belong in this app unless handled by the provider's secured elements.
4. Connect transactional email/SMS, implement idempotent outbox delivery and scheduled reminders, confirm consent preferences, and add delivery monitoring. Test cancellation and rescheduling messages against the latest appointment state.
5. Approve intake/consent forms and privacy terms, add service-specific assignment, data export/deletion, and access audit tooling. Add owner controls for catalog and staff management.
6. Activate the existing linked Vercel project’s account and booking capabilities once the database adapter is deployment-safe. Validate preview authentication, availability races, rescheduling/cancellation, payments/webhooks, delivery, backups, mobile accessibility, and failure recovery before opening live booking.

Deployment status: the September update includes the custom booking engine, Recovery intake, Business OS, and immersive public experiences in source. On Vercel, booking and account pages show an explicit not-open state, protected workspaces require authentication, and shared API endpoints return 503 without accessing local storage. The database guard remains intentional; deploying this code does not activate live booking, payments, or messaging. Migrate the storage adapter before enabling those capabilities. See [Booking](BOOKING.md) and [Business OS](BUSINESS-OS.md) for the implemented features and configuration.

Subsequent product expansion: waitlists, recurring bookings, automatic rebooking suggestions, operational utilization and cohort retention, aftercare/files, loyalty, memberships, retail/gift cards, and multi-location management. PWA install metadata and approved raster icons are present; an offline shell, update prompts, and push registration are still pending. Never cache private appointment payloads in a general service worker cache.
